# 0004 — Detect edit conflicts with a revision per cell

- **Status:** Accepted
- **Date:** 2026-09-27
- **Deciders:** Maksym (owner) with Claude during the design walk

## Context

Two or three partners can edit one shared page at once. Saving the same cell must never silently drop either value (AC-11); changes to different cells must both be kept (AC-12); a delete must not remove a row someone changed during its 5-second Undo (AC-15b). Live co-editing is a non-goal (spec §3).

## Decision drivers

- spec §6: lost edits under concurrent editing = 0.
- AC-11, AC-12, AC-15, AC-15b, AC-19 (a column autofill writes many cells while others edit).
- ADR-0003: D1 supports conditional updates inside one batch.

## Considered options

1. **A revision per cell** — word, translation and definition of every row each carry the revision they were last changed at; a save names the revision it started from.
2. **A revision per row** — one revision for the whole row.

## Decision outcome

**Chosen:** option 1. Each session has one revision counter that goes up with every write; each cell stores the session revision of its last change. A save sends the row id, the field, the new value and the cell's revision as the client saw it; D1 applies it only if the cell still has that revision, and otherwise answers with the current value and revision, which the page shows beside the partner's own for them to choose (AC-11). Different cells — including different cells of the same row — never conflict, so a column autofill running beside a partner's typing does not raise false conflicts.

Rows have a stable id generated by the client that adds them, so a new row is inserted when its first cell receives text (AC-13) without a second round trip. Delete with Undo is client-side: the page hides the row for 5 s, then sends the delete with the revisions of all three cells; any mismatch means someone changed the row, the delete is not applied, and the partner is told (AC-15b). Closing the page within 5 s never sends the delete (AC-15).

## Consequences

**Positive**
- The same per-cell revision is the polling cursor (ADR-0005): "cells changed since revision N" needs no separate change log.
- Conflicts are raised only when two people really changed the same text.

**Negative**
- Three revision values per row, and the delete check compares all three.
- Deleted rows must leave a tombstone (a row marked deleted at a revision) so polling pages learn about the delete.

**Neutral**
- A merge of two values is never attempted; the partner always chooses.
